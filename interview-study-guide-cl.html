Expert-level C# 7 questions

The interviewer wants to see that you understand what the runtime does with your code, not only the syntax.

COREWhat is the difference between a class, a struct, a record and a record struct?

class is a reference type on the heap; assignment copies the reference. struct is a value type; assignment copies the whole value, and it lives inline (on the stack or inside its containing object). record (a record class) is a reference type with compiler-generated value-based equality, ToString, deconstruction and non-destructive mutation via with. record struct gives the same conveniences to a value type.

  • Use structs for small, immutable, short-lived values (≈16 bytes or less); large structs are costly to copy.
  • Casting a struct to object or an interface causes boxing, an allocation that hurts in hot paths.
  • Records are ideal for DTOs, value objects and messages.

SENIORExplain what happens when you await a Task. What are ConfigureAwait(false) and ValueTask for?

The compiler rewrites an async method into a state machine. At an await, if the task isn't complete, the method returns to its caller and registers a continuation. When the task completes, the continuation resumes the state machine, by default on the captured SynchronizationContext (UI thread in WPF/WinForms) or the thread pool.

  • ConfigureAwait(false) says "don't resume on the captured context". It matters in library code and UI apps. ASP.NET Core has no SynchronizationContext, so it changes little there, but libraries should still use it.
  • Calling .Result or .Wait() on async code (sync-over-async) can deadlock where a context exists and starves the thread pool everywhere else.
  • ValueTask avoids a Task allocation when the result is often available synchronously (e.g. a cache hit). Rules: await it once, never twice, and don't await it concurrently.

Follow-up to expect: "Why is async void dangerous?" Exceptions can't be caught by the caller and crash the process; use it only for event handlers.

SENIORHow does the .NET garbage collector work, and when do you implement IDisposable?

The GC is generational: Gen 0 (new, collected often), Gen 1 (buffer), Gen 2 (long-lived). Objects of 85,000 bytes or more go to the Large Object Heap, which is collected with Gen 2 and isn't compacted by default, so large temporary arrays cause fragmentation (use ArrayPool<T>).

The GC only manages memory. IDisposable is for deterministic release of other resources: connections, file handles, sockets. Use using / await using (IAsyncDisposable). A finalizer is only needed when you directly own an unmanaged handle, and even then prefer SafeHandle.

EXPERTWhat are Span<T> and Memory<T>, and when would you use them?

Span<T> is a ref struct that represents a contiguous region of memory (array, stack memory via stackalloc, or native memory) without copying. Slicing a span is free, which makes parsing and string handling allocation-free. Because it's a ref struct it can only live on the stack: no fields in classes, no boxing, and no crossing an await.

Memory<T> is the heap-storable equivalent you can keep in fields and pass across await; you call .Span when you need to work on it.

ReadOnlySpan<char> line = "2026-10-07;ORDER;42";
int first = line.IndexOf(';');
ReadOnlySpan<char> date = line[..first];   // no new string allocated

SENIORWhat's the difference between IEnumerable<T>, ICollection<T>, IList<T> and IReadOnlyList<T>? Which do you return from a method?

IEnumerable only supports iteration and may be lazy (it could re-run a query each time you enumerate it). ICollection adds Count, Add/Remove. IList adds index access. IReadOnlyList/IReadOnlyCollection expose count and indexing without mutation.

Return the most specific read-only type that is honest about the data: if you've materialized results, return IReadOnlyList<T> so callers know it's already in memory and can't mutate it. Accept the most general type you need as parameters.

EXPERTExplain covariance and contravariance with an example.

Variance applies to generic interfaces and delegates. Covariance (out T) lets you use a more derived type where a less derived one is expected for outputs: IEnumerable<string> can be assigned to IEnumerable<object>. Contravariance (in T) works the other way for inputs: an IComparer<object> can be used as an IComparer<string>. List<T> is invariant because T is both read and written.

COREHow do you use nullable reference types and pattern matching to write safer code?

With <Nullable>enable</Nullable> the compiler tracks whether a reference can be null and warns on dereferences. string? declares intent; treat warnings as errors in new projects. Pattern matching makes branching on shape explicit and exhaustive:

decimal Fee(Payment p) => p switch
{
    Card { Amount: > 1000 } c  => c.Amount * 0.015m,
    Card c                     => c.Amount * 0.025m,
    Transfer                   => 5m,
    null                       => throw new ArgumentNullException(nameof(p)),
    _                          => throw new NotSupportedException()
};

.NET 8 / 9 5 questions

Checks that you keep up with the platform and understand the support model a company has to plan around.

COREWhat's the difference between LTS and STS releases, and where do .NET 8 and 9 stand today?

Even-numbered releases are LTS (Long-Term Support); odd-numbered ones are STS (Standard-Term Support). .NET 8 (Nov 2023) is LTS; .NET 9 (Nov 2024) is STS. Microsoft extended STS support to 24 months, so .NET 8 and .NET 9 both reach end of support in November 2026. .NET 10 (Nov 2025) is the current LTS and the natural upgrade target.

Good answer to add: "If I joined, one of my first checks would be the upgrade plan to .NET 10, since 8 and 9 stop getting security patches next month." Verify dates on Microsoft's support policy page before the interview.

SENIORName features from .NET 8 you've used or would use.

  • C# 12: primary constructors for classes, collection expressions (int[] x = [1, 2, 3];), default lambda parameters.
  • Keyed DI services: AddKeyedSingleton<IStorage, BlobStorage>("blob") and [FromKeyedServices("blob")].
  • Native AOT for ASP.NET Core minimal APIs: fast startup, small memory, for containers and serverless.
  • TimeProvider abstraction, so time-dependent code is testable.
  • IExceptionHandler for centralized exception handling.
  • FrozenDictionary / FrozenSet for read-heavy lookups built once.
  • Identity API endpoints (MapIdentityApi) and built-in metrics.

SENIORAnd .NET 9?

  • HybridCache: a two-level cache (in-memory + distributed) with stampede protection, replacing hand-written cache-aside code.
  • Built-in OpenAPI document generation (AddOpenApi() / MapOpenApi()); new templates no longer include Swashbuckle.
  • C# 13: params collections (params ReadOnlySpan<T>), the new System.Threading.Lock type.
  • LINQ: CountBy, AggregateBy, Index.
  • Task.WhenEach, MapStaticAssets for compressed, fingerprinted static files, and broad runtime performance gains.

EXPERTWhat are the trade-offs of Native AOT?

Benefits: very fast startup, lower memory, a single self-contained binary, no JIT. Costs: no runtime code generation, so reflection-heavy libraries break unless they use source generators. You need source-generated JSON (JsonSerializerContext), minimal APIs instead of MVC controllers, and EF Core support is still limited. Builds are slower and platform-specific. It fits serverless functions and high-density microservices, not every app.

COREMinimal APIs or controllers? How do you choose?

Minimal APIs are lighter, faster to start, AOT-friendly, and pair well with vertical slices; organize them with MapGroup, endpoint filters and TypedResults. Controllers give conventions, filters, model binding attributes and familiarity for large teams. Both have the same performance class in practice. I choose minimal APIs for new microservices and keep controllers in existing codebases rather than mixing styles without a reason.

ASP.NET Core 6 questions

Tests whether you understand the request pipeline and the framework's extension points.

COREExplain the middleware pipeline. Why does order matter?

Each middleware receives the HttpContext, can do work, call next() to pass the request on, and do more work on the way back. Middleware runs in registration order on the request and in reverse on the response. Order matters because, for example, authentication must run before authorization, and exception handling must be first so it wraps everything.

app.UseExceptionHandler();
app.UseHttpsRedirection();
app.UseCors("spa");
app.UseAuthentication();
app.UseAuthorization();
app.UseRateLimiter();
app.MapControllers();

Use chains to the next middleware, Run terminates the pipeline, Map branches by path.

SENIORMiddleware vs filters: when do you use each?

Middleware sees every request and knows nothing about MVC (no action, no model). Use it for cross-cutting HTTP concerns: logging, correlation IDs, exception handling, headers. Filters (authorization, resource, action, exception, result) run inside the MVC/endpoint pipeline and have access to the action, its arguments and model state. Use them for concerns tied to endpoints, like validation or auditing specific actions. Minimal APIs use endpoint filters (AddEndpointFilter).

SENIORHow do you implement global error handling that returns consistent responses?

Register AddProblemDetails() and an IExceptionHandler implementation, then app.UseExceptionHandler(). Map known exceptions (validation, not found, conflict) to the correct status codes and return RFC 9457 ProblemDetails JSON, with a trace ID for correlation. Never leak stack traces outside Development. Expected business failures are often better modeled as result types than exceptions.

public class AppExceptionHandler(ILogger<AppExceptionHandler> log) : IExceptionHandler
{
    public async ValueTask<bool> TryHandleAsync(HttpContext ctx, Exception ex, CancellationToken ct)
    {
        var (status, title) = ex switch {
            NotFoundException   => (404, "Resource not found"),
            ValidationException => (400, "Validation failed"),
            _                   => (500, "Unexpected error")
        };
        log.LogError(ex, "Request failed");
        ctx.Response.StatusCode = status;
        await ctx.Response.WriteAsJsonAsync(new ProblemDetails { Status = status, Title = title }, ct);
        return true;
    }
}

COREExplain the Options pattern. What's the difference between IOptions, IOptionsSnapshot and IOptionsMonitor?

The Options pattern binds a configuration section to a strongly typed class: builder.Services.AddOptions<SmtpOptions>().BindConfiguration("Smtp").ValidateDataAnnotations().ValidateOnStart();

  • IOptions<T>: singleton, read once, never reloads.
  • IOptionsSnapshot<T>: scoped, re-reads per request; can't be injected into singletons.
  • IOptionsMonitor<T>: singleton, gives the current value and an OnChange callback; use in singletons and background services.

Secrets go in User Secrets locally and Key Vault (or equivalent) in production, never in appsettings.json.

SENIORHow do you run background work in ASP.NET Core?

Inherit from BackgroundService and register with AddHostedService. Respect the stoppingToken for graceful shutdown. Because hosted services are singletons, create a scope with IServiceScopeFactory to use scoped services like a DbContext. For queued work use a Channel<T>. For durable, retryable or scheduled jobs, use a real queue or a library like Hangfire/Quartz, because in-memory work is lost on restart.

SENIORWhat built-in tools do you use to make an API fast and protect it under load?

  • Output caching (AddOutputCache) caches responses on the server, with tags for invalidation; response caching relies on HTTP cache headers.
  • Rate limiting middleware: fixed window, sliding window, token bucket, concurrency limiters, per user or per IP; returns 429.
  • Response compression, async I/O everywhere, CancellationToken passed through, pooled DbContext, avoiding sync-over-async.
  • Health checks (MapHealthChecks) for liveness/readiness probes.

REST API Development 5 questions

Checks API design judgment: semantics, consistency, and how clients will consume what you build.

COREWhat makes an API RESTful? How do you design resource URLs?

REST constraints: client-server, statelessness, cacheability, uniform interface, layered system. In practice: resources are nouns, HTTP verbs carry the action, and status codes carry the outcome.

  • GET /orders?status=open&page=2, GET /orders/42, POST /orders, PUT /orders/42, PATCH /orders/42, DELETE /orders/42
  • Sub-resources for ownership: GET /customers/7/orders
  • Plural nouns, lowercase, no verbs. For actions that aren't CRUD, model a resource: POST /orders/42/cancellation.

COREWhich HTTP methods are idempotent? What's the difference between PUT and PATCH?

Safe (no side effects): GET, HEAD, OPTIONS. Idempotent (repeating gives the same result): GET, PUT, DELETE, HEAD, OPTIONS. POST is neither; PATCH is not guaranteed to be idempotent. PUT replaces the entire resource; PATCH applies a partial update (JSON Merge Patch or JSON Patch).

To make POST safe to retry (e.g. payments), accept an Idempotency-Key header and store the result per key so a retried request returns the original response.

COREWhich status codes do you use and when?

CodeUse
200 / 201 / 204OK with body · Created (with Location header) · No content
400 / 422Malformed request or validation failure
401 / 403Not authenticated · authenticated but not allowed
404 / 409Not found · conflict (duplicate, concurrency)
412 / 429Precondition failed (ETag mismatch) · too many requests
500 / 503Server error · temporarily unavailable

SENIORHow do you version an API, and how do you avoid breaking clients?

Options: URL segment (/v1/orders, most visible), query string (?api-version=1.0), header, or media type. I prefer URL segments for public APIs, using the Asp.Versioning package. More important than the scheme is avoiding breaking changes: add fields instead of renaming, never change field meaning, keep old versions alive with a published deprecation schedule (the Deprecation/Sunset headers), and use contract tests.

SENIORHow do you implement pagination, filtering and optimistic concurrency in an API?

  • Pagination: offset (page/pageSize) is simple but slow on deep pages and unstable when data changes. Cursor/keyset pagination (?after=lastId) is fast and stable for large or live data. Always cap the page size.
  • Filtering/sorting: whitelist allowed fields; never build SQL from raw input.
  • Concurrency: return an ETag (from a rowversion column). The client sends If-Match on update; if it doesn't match, return 412. That prevents lost updates.

Microservices Architecture 5 questions

The interviewer wants trade-off thinking, not enthusiasm. Saying when not to use microservices is a strong signal.

SENIORWhen would you choose microservices over a monolith, and when not?

Microservices pay off when you need independent deployment and scaling, multiple teams owning separate business capabilities, or different technology needs. They cost a lot: network latency and failures, distributed data, eventual consistency, observability, and DevOps maturity.

For a new product or a small team, I'd start with a modular monolith with strict module boundaries (one bounded context per module, no shared tables). Extract services later where there's a proven need. A "distributed monolith", services that must deploy together, is the worst of both.

SENIORHow should services communicate?

  • Synchronous (HTTP/REST, gRPC): simple, immediate response, but creates temporal coupling; a chain of calls multiplies latency and failure probability. gRPC suits internal, high-throughput calls with strong contracts.
  • Asynchronous (messages/events via RabbitMQ, Azure Service Bus, Kafka): decoupled and resilient; the consumer can be down. Costs: eventual consistency, harder debugging.

Rule of thumb: queries can be sync; state changes that other services react to should be async events.

EXPERTEach service owns its database. How do you handle a business transaction spanning several services?

You can't use a distributed ACID transaction in practice (2PC doesn't scale and brokers don't support it). Use a Saga: a sequence of local transactions where each step publishes an event or command, and failures trigger compensating actions (refund payment, release stock).

  • Choreography: services react to each other's events. Low coupling, but the flow is hard to see.
  • Orchestration: a central orchestrator (e.g. MassTransit state machine, Durable Functions) tells each service what to do. Easier to follow and monitor.

Combine with the transactional outbox so saving data and publishing the event can't get out of sync, and make every step idempotent.

SENIORHow do you make a service resilient to failures in its dependencies?

Use Microsoft.Extensions.Http.Resilience (built on Polly v8): AddStandardResilienceHandler() on an HttpClient adds:

  • Timeouts per attempt and total.
  • Retries with exponential backoff and jitter, only for transient errors and idempotent operations.
  • Circuit breaker to stop hammering a failing dependency.
  • Rate limiter / bulkhead to isolate resources.

Also: fallbacks and caching for degraded mode, health checks, and never an unbounded call chain.

SENIORWhat infrastructure does a microservices system need around the services?

  • API Gateway (YARP, Azure API Management): single entry, routing, auth, rate limiting. A BFF per client type if needs differ.
  • Observability: distributed tracing, metrics and structured logs via OpenTelemetry, with a correlation ID across calls.
  • Containers and orchestration: Docker, Kubernetes or Azure Container Apps; service discovery, config, secrets.
  • CI/CD per service and contract testing.
  • .NET Aspire helps with local orchestration, service defaults and telemetry wiring.

Event-Driven Architecture 5 questions

Expect probing on delivery guarantees. Most real bugs in event systems come from duplicates and ordering.

COREWhat's the difference between a command, an event and a query?

A command asks one specific handler to do something and can be rejected (PlaceOrder, imperative). An event states that something already happened (OrderPlaced, past tense), has zero or many subscribers, and can't be rejected. A query asks for data without changing state. Commands go to a queue; events are published to a topic.

SENIORWhat delivery guarantees do message brokers give, and how do you handle duplicates?

At-most-once (may lose messages), at-least-once (may duplicate, the common default), exactly-once (only within narrow boundaries). Design for at-least-once by making consumers idempotent:

  • Store processed message IDs (an inbox table) and skip repeats, in the same transaction as the work.
  • Use natural idempotency: upserts, "set status = Paid" instead of "add 100".
  • Poison messages go to a dead-letter queue after N retries, with alerting.

EXPERTExplain the transactional outbox pattern.

Problem: you save an order to the database and then publish OrderPlaced. If the publish fails after the commit, or the commit fails after the publish, systems disagree. The outbox writes the event into an Outbox table in the same database transaction as the business data. A separate relay (background service, or CDC) reads unsent rows, publishes them, and marks them sent. This gives at-least-once publishing, so consumers must be idempotent. MassTransit and NServiceBus have built-in outbox support with EF Core.

EXPERTHow do you deal with message ordering?

Global ordering doesn't scale. Order only where it matters, usually per entity: in Kafka use the entity ID as the partition key; in Azure Service Bus use sessions with the entity ID as the session ID. Consumers should still tolerate out-of-order arrival with a version number or timestamp on each event and ignore stale ones.

EXPERTWhat are event sourcing and CQRS, and do they have to go together?

CQRS separates the write model (commands, rich domain validation) from read models optimized for queries. Event sourcing stores the sequence of events as the source of truth, and current state is rebuilt by replaying them, which gives a full audit trail and time travel. They pair well (events project into read models) but are independent: CQRS is often used alone with a normal database. Event sourcing adds complexity: event versioning, snapshots, projections, eventual consistency. Use it where the history itself is valuable, such as ledgers or compliance.

Entity Framework Core 6 questions

Most production EF issues are about performance. Show you know what SQL your code generates.

COREWhat is change tracking, and when do you use AsNoTracking?

The DbContext keeps snapshots of loaded entities and detects changes at SaveChanges. Tracking costs memory and CPU. For read-only queries use AsNoTracking() (or set QueryTrackingBehavior.NoTracking as default for read-heavy contexts). AsNoTrackingWithIdentityResolution() avoids duplicate instances of the same entity in the result graph.

SENIORWhat is the N+1 problem and how do you fix it in EF Core?

Loading a list and then lazily loading a navigation property for each item runs 1 + N queries. Fixes:

  • Projection with Select into a DTO: only needed columns, one query. Usually the best option for reads.
  • Include/ThenInclude for eager loading.
  • AsSplitQuery() when multiple collection includes cause a "cartesian explosion" of rows.
  • Avoid lazy loading proxies in web apps.
var orders = await db.Orders
    .Where(o => o.CustomerId == id)
    .Select(o => new OrderDto(o.Id, o.Total, o.Lines.Count))
    .ToListAsync(ct);

SENIORHow do you handle concurrency conflicts?

Optimistic concurrency: add a [Timestamp] byte[] RowVersion (SQL Server rowversion) or a concurrency token. EF adds it to the WHERE clause of updates; if no row is affected it throws DbUpdateConcurrencyException. Then you decide: return 409 to the client, reload and retry, or merge values.

SENIORHow do you apply migrations to production safely?

Don't call Database.Migrate() at app startup in multi-instance deployments (race conditions, app needs DDL rights). Generate an idempotent script (dotnet ef migrations script --idempotent) or a migration bundle (efbundle) and run it in the CD pipeline, reviewed. Design backward-compatible changes (expand/contract): add a nullable column, deploy code, backfill, then tighten. Review generated SQL for data loss.

SENIORHow do you do bulk updates and deletes efficiently?

Since EF Core 7, ExecuteUpdateAsync and ExecuteDeleteAsync translate directly to a single SQL statement without loading entities:

await db.Orders.Where(o => o.CreatedAt < cutoff && o.Status == Status.Draft)
    .ExecuteDeleteAsync(ct);

They bypass change tracking and interceptors, so in-memory entities don't see the change. For massive inserts, use SqlBulkCopy or a bulk extension library.

EXPERTShould you wrap EF Core in a generic repository? What other performance features exist?

DbContext is already a Unit of Work and DbSet a repository. A generic IRepository<T> with GetAll/Find usually hides useful EF features and leaks IQueryable anyway. A repository per aggregate root with intention-revealing methods is reasonable in DDD-style code. Be ready to argue both sides.

Other performance tools: DbContext pooling (AddDbContextPool), compiled queries (EF.CompileAsyncQuery), raw SQL with FromSql/SqlQuery, logging generated SQL, global query filters for soft delete and multi-tenancy.

LINQ 4 questions

Often a live coding question. Know execution semantics, not just operators.

COREWhat is deferred execution? What's the danger of multiple enumeration?

Most LINQ operators build a query that runs only when enumerated (foreach, ToList, Count, First). Enumerating the same IEnumerable twice runs it twice, which against a database means two queries, and against a generator may give different results. Materialize once with ToList() when you need to iterate multiple times.

SENIORWhat's the difference between IEnumerable and IQueryable in LINQ?

IQueryable holds an expression tree that a provider (EF Core) translates into SQL, so filtering runs in the database. IEnumerable runs delegates in memory. If you call AsEnumerable() or ToList() too early, or your method takes IEnumerable, the rest of the filtering happens in memory after fetching everything. EF Core throws when it can't translate an expression in a filter, for example a custom C# method.

COREFirst vs FirstOrDefault vs Single vs SingleOrDefault; Any() vs Count() > 0?

First throws if empty; FirstOrDefault returns default. Single throws if zero or more than one match, so it asserts uniqueness (and in SQL fetches TOP 2). Use Any() to check existence: it stops at the first match (EXISTS in SQL), while Count() may scan everything.

SENIORLive coding: from a list of orders, get the top 3 customers by total spent in 2026, with order counts.

var top = orders
    .Where(o => o.Date.Year == 2026)
    .GroupBy(o => o.CustomerId)
    .Select(g => new { CustomerId = g.Key, Total = g.Sum(o => o.Amount), Orders = g.Count() })
    .OrderByDescending(x => x.Total)
    .Take(3)
    .ToList();

Also know SelectMany (flattening a collection of collections), Join/GroupJoin, ToDictionary/ToLookup, Chunk, DistinctBy/MaxBy (.NET 6) and CountBy (.NET 9). In EF, filter by a date range instead of .Year so the query can use an index.

SQL Server 6 questions

Expect questions on indexing and on diagnosing a slow query from an execution plan.

COREClustered vs nonclustered index? What is a covering index?

A clustered index defines the physical order of the table's rows; one per table, usually the primary key. A narrow, ever-increasing key (INT IDENTITY, sequential GUID) avoids page splits. A nonclustered index is a separate structure with the key and a pointer to the row. If a query needs columns not in the index, SQL Server does a key lookup per row. A covering index includes all needed columns via INCLUDE, eliminating lookups. Filtered indexes (WHERE IsActive = 1) are smaller for selective subsets.

CREATE NONCLUSTERED INDEX IX_Orders_Customer_Date
ON dbo.Orders (CustomerId, OrderDate DESC)
INCLUDE (Total, Status);

SENIORA query is slow. Walk me through how you'd investigate.

  • Reproduce with real parameters; check SET STATISTICS IO, TIME ON and the actual execution plan.
  • Look for scans on large tables, key lookups, big estimated-vs-actual row differences (stale statistics), spills to tempdb, implicit conversions.
  • Check SARGability: functions on columns (WHERE YEAR(OrderDate) = 2026), leading wildcards, or type mismatches prevent index seeks.
  • Use Query Store to find regressions and plan changes over time, and DMVs for top resource consumers.
  • Then fix: rewrite the predicate, add/adjust an index, update statistics, and verify the plan again.

EXPERTWhat is parameter sniffing and how do you deal with it?

SQL Server compiles a plan using the first parameter values it sees and caches it. If data is skewed (one customer has 1M orders, most have 10), a plan good for one value can be terrible for another. Options: OPTION (RECOMPILE) for infrequent queries, OPTIMIZE FOR a representative value, splitting into separate queries, or Query Store plan forcing. SQL Server 2022's Parameter Sensitive Plan optimization can cache multiple plans automatically.

SENIORExplain isolation levels and how you'd reduce blocking and deadlocks.

Read Uncommitted (dirty reads), Read Committed (default), Repeatable Read, Serializable, plus row-versioning options: Read Committed Snapshot (RCSI) and Snapshot. With RCSI, readers see the last committed version and don't block writers, which removes most reader/writer blocking (costs tempdb space). Avoid NOLOCK: it can return missing or duplicate rows.

Deadlocks: keep transactions short, access tables in a consistent order, have proper indexes so fewer rows are locked, retry the victim (error 1205), and analyze the deadlock graph from the system_health Extended Events session.

CORETemp table vs table variable vs CTE?

CTE: a named subquery for readability or recursion; not materialized, re-evaluated if referenced twice. Temp table (#t): in tempdb, has statistics and indexes, best for larger intermediate results. Table variable (@t): limited statistics (improved by deferred compilation since 2019), fine for small sets; survives transaction rollback.

SENIORWrite a query that returns each customer's most recent order.

WITH ranked AS (
    SELECT o.*, ROW_NUMBER() OVER (PARTITION BY CustomerId ORDER BY OrderDate DESC) AS rn
    FROM dbo.Orders o
)
SELECT * FROM ranked WHERE rn = 1;

Know the other window functions: RANK/DENSE_RANK, LAG/LEAD, and running totals with SUM() OVER (ORDER BY ... ROWS UNBOUNDED PRECEDING). CROSS APPLY (SELECT TOP 1 ...) is an alternative that can be faster with the right index.

NoSQL Databases 4 questions

Checks that you choose storage by access pattern, and know how NoSQL modeling differs from relational.

COREWhat types of NoSQL databases exist and when would you choose one over SQL Server?

  • Document (Azure Cosmos DB, MongoDB): flexible JSON, aggregates read as a unit (catalogs, user profiles).
  • Key-value (Redis): caching, sessions, counters, rate limits.
  • Wide-column (Cassandra): massive write throughput, time series.
  • Graph (Neo4j, Cosmos Gremlin): relationship traversal (recommendations, fraud).

Choose NoSQL for horizontal scale, schema flexibility, or specific access patterns. Keep relational for complex joins, ad-hoc reporting and strong multi-entity transactions. Polyglot persistence is common: SQL for orders, Redis for cache, a document store for the catalog.

SENIORHow do you model data in a document database?

Model for the queries, not for normalization. Embed data read together and bounded in size (order with its lines). Reference data that's large, unbounded or shared and updated independently. Denormalization is normal; keep copies in sync via change feed or events. Avoid unbounded arrays inside a document.

EXPERTIn Cosmos DB, why is the partition key so important?

The partition key determines how data is distributed and is fixed once the container is created. A good key has high cardinality, spreads requests evenly (no hot partition), and is included in most queries, so they stay single-partition; cross-partition queries cost more RUs. Transactions only work within one logical partition. Typical choices: tenantId, userId, or a hierarchical key. Also know the consistency levels: Strong, Bounded Staleness, Session (default), Consistent Prefix, Eventual.

SENIORHow would you use Redis in a .NET system? What's the CAP theorem's relevance?

Redis: distributed cache (cache-aside, or HybridCache with Redis as L2), session store, rate-limit counters, pub/sub, distributed locks (carefully), leaderboards with sorted sets. Set TTLs, plan invalidation, and protect against cache stampede.

CAP: under a network partition a distributed store must choose Consistency or Availability. Most NoSQL systems let you tune this (Cosmos consistency levels, Cassandra quorum). PACELC adds that, even without partitions, you trade latency against consistency.

Dependency Injection 4 questions

Lifetimes and the captive dependency bug come up in almost every .NET interview.

COREExplain the three service lifetimes and what a captive dependency is.

Transient: new instance every resolution. Scoped: one per scope; in ASP.NET Core, one per HTTP request (DbContext is scoped). Singleton: one for the app's lifetime; must be thread-safe.

A captive dependency is a longer-lived service holding a shorter-lived one, e.g. a singleton receiving a scoped DbContext: the context lives forever, isn't thread-safe and goes stale. Development mode enables scope validation, which throws at startup. Fix it by injecting IServiceScopeFactory and creating a scope when needed, or IDbContextFactory<T>.

SENIORHow do you register and choose between multiple implementations of one interface?

  • Register several and inject IEnumerable<INotifier> to use all of them (e.g. send by email and SMS).
  • Use keyed services (.NET 8+) to pick one by key: [FromKeyedServices("sms")] INotifier n.
  • Use a factory or strategy resolver when the choice depends on runtime data.
  • TryAdd* avoids overriding an existing registration (important in libraries).

SENIORWhy is the Service Locator pattern considered an anti-pattern?

Injecting IServiceProvider and calling GetService everywhere hides dependencies: you can't see from the constructor what a class needs, missing registrations fail at runtime, and tests are harder. Prefer constructor injection. Valid exceptions: composition roots, factories, and creating scopes in singletons/background services.

EXPERTHow do you add cross-cutting behavior (caching, logging) without changing a service?

Use the Decorator pattern: CachedProductService implements IProductService and wraps the real one. The built-in container doesn't support decoration directly; use Scrutor's services.Decorate<IProductService, CachedProductService>() or register by factory. In MediatR-style designs, pipeline behaviors serve the same purpose for all handlers.

Clean Architecture 4 questions

They want you to explain the dependency rule and also show pragmatism about its cost.

COREDescribe Clean Architecture and the dependency rule.

Concentric layers with dependencies pointing inward only:

  • Domain: entities, value objects, domain events, business rules. No dependencies on frameworks.
  • Application: use cases (commands/queries, handlers), interfaces for what it needs (IOrderRepository, IEmailSender), DTOs, validation.
  • Infrastructure: implementations: EF Core, external APIs, file storage, messaging.
  • Presentation/API: controllers or endpoints, composition root (DI wiring).

The benefit: business logic is testable without a database or web server, and infrastructure can change without touching the core.

SENIORWhere does each of these go: an EF Core configuration, a validation rule, an IEmailSender interface, an SMTP implementation, a DTO?

EF configuration → Infrastructure. Business invariants → Domain; input validation (FluentValidation) → Application. IEmailSender → Application (the core defines what it needs). SMTP implementation → Infrastructure. Request/response DTOs → Application or API depending on whether they're use-case contracts or transport models.

SENIORWhat are the downsides of Clean Architecture? What about Vertical Slice Architecture?

Downsides: lots of projects, interfaces and mapping for simple CRUD; a feature change touches many folders. Vertical Slice organizes code by feature (each endpoint/use case owns its request, handler, validation and data access), keeping changes local. Many teams combine them: slices inside the Application layer with a rich Domain where business rules are complex. Match ceremony to complexity.

SENIORHow do you implement CQRS in a Clean Architecture solution? Do you need MediatR?

Commands change state through the domain model; queries go straight to read-optimized data (projections, Dapper, views), skipping the domain. MediatR is a common in-process dispatcher with pipeline behaviors for validation, logging and transactions. You don't need it: plain handler classes injected directly work fine. Note that MediatR (and AutoMapper) moved to commercial licensing for business use in 2025, so many teams now use plain handlers or alternatives.

Domain-Driven Design (DDD) 5 questions

Strong candidates explain the strategic side (boundaries, language), not only entities and repositories.

COREWhat's the difference between strategic and tactical DDD?

Strategic DDD is about the big picture: the ubiquitous language shared with domain experts, bounded contexts (where a model and its terms are consistent), subdomains (core, supporting, generic) and context maps describing how contexts integrate (anti-corruption layer, shared kernel, customer-supplier). Tactical DDD gives building blocks inside a context: entities, value objects, aggregates, domain events, domain services, repositories.

COREEntity vs value object?

An entity has an identity that persists across changes (Customer #42 stays the same customer when the address changes). A value object is defined only by its values, is immutable, and is replaced rather than modified (Money, Address, DateRange). Value objects carry validation and behavior, so you avoid primitive obsession.

public sealed record Money(decimal Amount, string Currency)
{
    public Money Add(Money other) => other.Currency == Currency
        ? this with { Amount = Amount + other.Amount }
        : throw new InvalidOperationException("Currency mismatch");
}

SENIORWhat is an aggregate, and what rules apply to it?

  • A cluster of entities and value objects treated as one consistency boundary, accessed only through the aggregate root (Order is the root; OrderLine is reached through it).
  • Invariants are enforced inside the aggregate (e.g. "an order total can't exceed the credit limit").
  • Reference other aggregates by ID, not object reference.
  • One transaction modifies one aggregate; cross-aggregate consistency is eventual, via domain events.
  • Keep aggregates small. One repository per aggregate root.

SENIORDomain events vs integration events?

Domain events are raised inside a bounded context, often dispatched in-process (before or after SaveChanges) to trigger side effects within the same service. Integration events cross service boundaries through a message broker, are versioned public contracts with only the data others need, and are published reliably via an outbox. A domain event handler often maps to an integration event.

SENIORWhat is an anemic domain model and why is it criticized?

Entities that are just property bags with public setters, with all logic in services. Invariants are scattered and easy to bypass. A rich model encapsulates behavior: private setters, methods like order.AddLine(product, qty) and order.Ship() that validate state. For simple CRUD, an anemic model is acceptable; DDD pays off in complex domains.

SOLID Principles 3 questions

Don't recite definitions only. Give a concrete example of a violation and how you fixed it.

COREExplain each SOLID principle with a short example.

  • S, Single Responsibility: a class has one reason to change. An InvoiceService that calculates, renders a PDF and emails should be split.
  • O, Open/Closed: open for extension, closed for modification. Add a new discount type by adding a class implementing IDiscountRule, not by editing a switch.
  • L, Liskov Substitution: subtypes must be usable wherever the base type is expected without surprises. A ReadOnlyRepository throwing on Save breaks LSP.
  • I, Interface Segregation: many small, client-specific interfaces instead of one fat interface (IReader / IWriter).
  • D, Dependency Inversion: high-level modules depend on abstractions, not on concrete low-level modules; the abstraction belongs to the high-level side.

SENIORIs Dependency Inversion the same as Dependency Injection?

No. Dependency Inversion is a design principle about the direction of dependencies (the Application layer owns IEmailSender; Infrastructure implements it). Dependency Injection is a technique for supplying dependencies from outside, and a DI container automates it. You can inject concrete classes without inverting anything, and you can invert dependencies with manual wiring.

SENIORCan applying SOLID go too far?

Yes: an interface for every class with one implementation, dozens of tiny classes, and abstractions for change that never comes. I add an abstraction when there's a real second implementation, a test seam I need, or a boundary (I/O, external systems). YAGNI and KISS balance SOLID.

Design Patterns 4 questions

Expect "which patterns have you used and why". Tie each to a real problem you solved.

COREWhich design patterns do you use most in .NET, and where?

  • Strategy: interchangeable algorithms (payment providers, pricing rules) selected at runtime.
  • Factory / Abstract Factory: creation logic that depends on input or configuration; IHttpClientFactory is a framework example.
  • Decorator: add caching, logging or retries around a service; ASP.NET middleware follows a similar chain idea.
  • Adapter: wrap a third-party SDK behind your own interface.
  • Repository / Unit of Work: persistence abstraction (EF's DbContext already is one).
  • Mediator: decouple senders from handlers (MediatR).
  • Observer: events, IObservable, domain events.
  • Builder: WebApplication.CreateBuilder, test data builders.
  • Options and Specification (reusable query criteria).

SENIORRefactor a large switch on payment type into a better design.

public interface IPaymentProcessor { string Method { get; } Task PayAsync(Order o); }

public class CardProcessor : IPaymentProcessor { public string Method => "card"; /* ... */ }
public class PayPalProcessor : IPaymentProcessor { public string Method => "paypal"; /* ... */ }

public class PaymentService(IEnumerable<IPaymentProcessor> processors)
{
    private readonly Dictionary<string, IPaymentProcessor> _map =
        processors.ToDictionary(p => p.Method);

    public Task PayAsync(Order o, string method) =>
        _map.TryGetValue(method, out var p) ? p.PayAsync(o)
        : throw new NotSupportedException(method);
}

This is Strategy plus DI; adding a method means adding a class and a registration (Open/Closed). Keyed services are an alternative.

SENIORWhat are the problems with the classic Singleton pattern?

Global state, hidden dependencies, hard to test or replace, and thread-safety concerns. In .NET, register a singleton lifetime in the DI container instead; you get one instance without a static accessor. If you must hand-roll one, use Lazy<T> for thread-safe lazy initialization.

SENIORDecorator vs inheritance: why prefer composition?

Inheritance fixes behavior at compile time and leads to class explosion (CachedLoggedRetryingService). Decorators compose at runtime in any order, each with one responsibility, and work with sealed classes and interfaces. "Favor composition over inheritance" is the guiding rule.

Authentication & Authorization (OAuth2, OIDC, JWT) 6 questions

Security answers must be precise. Mixing up OAuth2 and OIDC, or storing tokens carelessly, is a red flag.

COREAuthentication vs authorization? OAuth 2.0 vs OpenID Connect?

Authentication establishes who you are; authorization decides what you can do. OAuth 2.0 is an authorization framework: it lets a client get an access token to call an API on a user's behalf; it doesn't define user identity. OpenID Connect is an identity layer on top of OAuth 2.0: it adds the ID token (a JWT describing the authenticated user), the openid scope, the UserInfo endpoint and discovery metadata. Use OIDC to log users in; use OAuth access tokens to call APIs.

SENIORWhich OAuth 2.0 flows do you use and when?

  • Authorization Code + PKCE: for web apps, SPAs and mobile apps. The user logs in at the identity provider; the app exchanges a code for tokens. PKCE protects the code exchange.
  • Client Credentials: service-to-service, no user involved.
  • Device Code: TVs, CLIs.
  • Refresh Token: to get new access tokens without re-login.
  • Deprecated by OAuth 2.1 / current best practice: Implicit and Resource Owner Password flows.

COREWhat's inside a JWT and how does the API validate it?

Three Base64URL parts: header (algorithm, key ID), payload (claims: sub, iss, aud, exp, nbf, scopes, roles), and signature. It's signed, not encrypted, so never put secrets in it. The API validates the signature (fetching public keys from the issuer's JWKS endpoint), issuer, audience, expiry and lifetime.

builder.Services.AddAuthentication(JwtBearerDefaults.AuthenticationScheme)
    .AddJwtBearer(o => {
        o.Authority = "https://login.example.com/";
        o.Audience  = "orders-api";
    });

Prefer asymmetric signing (RS256/ES256) so only the issuer holds the private key; HS256 shares a secret with every validator.

SENIORJWTs can't be revoked easily. How do you handle logout and compromised tokens?

Keep access tokens short-lived (5–15 minutes) and use refresh tokens with rotation (each use issues a new one and invalidates the old; reuse detection revokes the family). Revoke refresh tokens on logout or compromise. For immediate revocation, keep a denylist of token IDs (jti) in a cache, or use reference tokens with introspection for high-security APIs.

SENIORWhere should a React SPA store tokens?

localStorage is readable by any script, so an XSS bug leaks the tokens. The recommended approach is the Backend-for-Frontend (BFF) pattern: the ASP.NET Core backend performs the OIDC flow, keeps tokens server-side, and gives the browser an HttpOnly, Secure, SameSite session cookie; the BFF proxies API calls and attaches tokens. Protect cookie-based endpoints from CSRF (SameSite plus an anti-forgery header). If tokens must live in the browser, keep them in memory only and use a library like MSAL or oidc-client-ts.

SENIORHow do you implement authorization in ASP.NET Core beyond roles?

  • Role-based: [Authorize(Roles = "Admin")], simple but coarse.
  • Policy-based: named policies combining claims, scopes and custom requirements: AddAuthorizationBuilder().AddPolicy("CanRefund", p => p.RequireClaim("scope", "orders.refund")).
  • Custom requirements and handlers (IAuthorizationHandler) for logic like "must be over 18" or "same tenant".
  • Resource-based: inject IAuthorizationService and call AuthorizeAsync(User, order, "EditOrder") to check ownership of a specific record.

Scopes describe what the client app may do; roles/claims describe what the user may do. Check both.

Frontend Development

React, TypeScript, the web platform and data flow

ReactJS 7 questions

Expect hooks, rendering behavior and performance. Knowing what changed in React 19 shows you're current.

COREHow does React decide what to update? Why do lists need keys?

When state or props change, React re-renders the component and its children, producing a new element tree. Reconciliation compares it with the previous tree and commits only the differences to the DOM. Elements of a different type replace the subtree. In lists, keys identify items across renders; with stable keys React can reorder and keep each item's state. Using the array index as key breaks when items are inserted, removed or reordered (state attaches to the wrong row). Use a stable ID.

COREExplain useEffect: dependencies, cleanup, and common mistakes.

useEffect synchronizes a component with something outside React (subscriptions, timers, DOM APIs, network). It runs after render; the dependency array controls when it re-runs; the returned function cleans up before the next run and on unmount.

useEffect(() => {
  const controller = new AbortController();
  fetch(`/api/orders/${id}`, { signal: controller.signal })
    .then(r => r.json()).then(setOrder)
    .catch(e => { if (e.name !== 'AbortError') setError(e); });
  return () => controller.abort();
}, [id]);
  • Missing dependencies cause stale values; objects/functions created in render as dependencies cause infinite loops.
  • Don't use effects to derive data from props/state; compute it during render.
  • In development, StrictMode mounts, unmounts and remounts to expose missing cleanup.

SENIORWhen do you use useMemo, useCallback and React.memo?

React.memo skips re-rendering a component when its props are shallowly equal. useCallback keeps a function reference stable and useMemo caches a computed value, mainly so memoized children or effect dependencies don't change on every render. Use them when profiling shows a cost (expensive calculation, large list, frequent re-render), not everywhere. The React Compiler (stable since late 2025) adds memoization automatically, which reduces the need for these by hand.

COREControlled vs uncontrolled components?

A controlled input's value lives in React state and changes through onChange; easy to validate and transform on each keystroke. An uncontrolled input keeps its value in the DOM and you read it with a ref or FormData, which is simpler and faster for large forms. Libraries like React Hook Form use uncontrolled inputs for performance. React 19's form Actions also work naturally with uncontrolled forms.

SENIORWhat's new in React 18 and React 19?

  • React 18: concurrent rendering, automatic batching of state updates everywhere, startTransition/useTransition for non-urgent updates, useDeferredValue, Suspense for data with streaming SSR, createRoot.
  • React 19: Actions (async functions in transitions, <form action={fn}>), useActionState, useFormStatus, useOptimistic, the use() API for promises and context, ref as a regular prop (no more forwardRef), document metadata tags, stable Server Components.

SENIORHow do you share logic between components? Write a custom hook.

function useDebounce<T>(value: T, delay = 300): T {
  const [debounced, setDebounced] = useState(value);
  useEffect(() => {
    const t = setTimeout(() => setDebounced(value), delay);
    return () => clearTimeout(t);
  }, [value, delay]);
  return debounced;
}

Custom hooks extract stateful logic (they replaced HOCs and render props for most cases). Rules of hooks: call them only at the top level of components or other hooks, never in conditions or loops, because React relies on call order.

SENIORHow do you handle errors and improve performance in a large React app?

  • Error boundaries (class component or react-error-boundary) catch render errors in a subtree and show a fallback. They don't catch errors in event handlers or async code.
  • Code splitting with React.lazy + Suspense per route.
  • Virtualize long lists (TanStack Virtual, react-window).
  • Keep state close to where it's used; split contexts; measure with React DevTools Profiler.

TypeScript 5 questions

Checks whether you use the type system to prevent bugs, not just to annotate.

COREinterface vs type?

Both describe object shapes. interface can be extended with extends and merged by redeclaration (useful for augmenting libraries). type aliases can also express unions, intersections, tuples, mapped and conditional types. A common convention: interface for public object contracts and props, type for unions and computed types. Consistency in the codebase matters more than the choice.

COREany vs unknown vs never?

any turns off checking. unknown accepts anything but forces you to narrow before use; it's the safe type for external data like API responses and catch errors. never is the type with no values: functions that always throw, and exhaustiveness checks.

function assertNever(x: never): never { throw new Error(`Unexpected: ${x}`); }

SENIORWhat are discriminated unions and how do you narrow them?

type RequestState<T> =
  | { status: 'idle' }
  | { status: 'loading' }
  | { status: 'success'; data: T }
  | { status: 'error'; error: string };

function render(s: RequestState<Order[]>) {
  switch (s.status) {
    case 'success': return s.data.length;   // data is available here
    case 'error':   return s.error;
    case 'idle': case 'loading': return null;
    default: return assertNever(s);         // compile error if a case is missing
  }
}

This makes impossible states unrepresentable (no "loading and error at the same time"). Other narrowing tools: typeof, instanceof, in, and user-defined type guards (x is Order).

SENIORExplain generics with constraints and the utility types you use.

function getProp<T, K extends keyof T>(obj: T, key: K): T[K] { return obj[key]; }

Utility types: Partial, Required, Readonly, Pick, Omit, Record, ReturnType, Parameters, Awaited, NonNullable. Example: type UpdateOrder = Partial<Omit<Order, 'id' | 'createdAt'>> for a PATCH payload.

SENIORWhat does strict mode enable, and what is satisfies?

"strict": true enables strictNullChecks, noImplicitAny, strict function types and more. Add noUncheckedIndexedAccess for safer array/record access. satisfies checks that a value matches a type while keeping its narrower inferred type:

const routes = { home: '/', orders: '/orders' } satisfies Record<string, string>;
// routes.orders keeps the literal type '/orders'

Remember that types disappear at runtime; validate external data with a schema library such as Zod.

JavaScript (ES6+) 6 questions

Fundamentals often come as "what does this code print?" questions.

COREvar vs let vs const; what is hoisting?

var is function-scoped and hoisted with the value undefined. let and const are block-scoped and hoisted into the temporal dead zone: accessing them before declaration throws. const prevents reassignment, not mutation of the object. Function declarations are fully hoisted. Default to const, use let when reassigning, avoid var.

COREWhat is a closure? Give a practical use.

A function keeps access to variables from the scope where it was created, even after that scope has finished. Uses: private state, factories, memoization, and event handlers and hooks in React (a stale closure is the classic hooks bug).

function counter() { let n = 0; return () => ++n; }
const next = counter(); next(); next(); // 2

SENIORExplain the event loop. What does this print?

console.log('A');
setTimeout(() => console.log('B'), 0);
Promise.resolve().then(() => console.log('C'));
console.log('D');

Output: A, D, C, B. Synchronous code runs on the call stack first. Then the event loop drains the microtask queue (promise callbacks, queueMicrotask) completely before taking the next macrotask (timers, I/O, UI events). Rendering happens between macrotasks, so long synchronous work freezes the UI.

COREHow does this work, and how do arrow functions differ?

In a regular function, this depends on how it's called: the object before the dot, undefined in strict mode for plain calls, or whatever call/apply/bind set. Arrow functions have no own this; they use the enclosing scope's. That makes them right for callbacks, but wrong as object methods that need the object.

SENIORPromise.all vs allSettled vs race vs any?

  • all: resolves with all results; rejects as soon as one rejects. For required parallel calls.
  • allSettled: waits for all, returns each status. For a dashboard where some widgets may fail.
  • race: settles with the first to settle (e.g. a timeout).
  • any: resolves with the first success; rejects only if all fail.

With async/await, avoid awaiting independent calls one by one in sequence; start them together and await Promise.all.

COREWhich ES6+ features do you use daily?

Destructuring and default values, spread/rest ({...obj}, [...arr]), template literals, arrow functions, classes, ES modules (import/export), optional chaining (a?.b), nullish coalescing (??, which unlike || keeps 0 and ''), Map/Set, array methods (map, filter, reduce, find, flatMap, at), immutable helpers (toSorted, toSpliced, with), structuredClone, Object.groupBy. Also === over == to avoid type coercion.

HTML5 4 questions

Usually about semantics and accessibility, which are easy to get right and often neglected.

COREWhy does semantic HTML matter?

Elements like header, nav, main, article, section, aside, footer, button and label carry meaning for screen readers, keyboard users, search engines and other developers. A <div onClick> isn't focusable or announced as a button; a real <button> gets keyboard support for free. Use one h1 and a logical heading order, alt text on images, and labels linked to inputs.

SENIORWhen do you use ARIA?

The first rule of ARIA: don't use it if a native element does the job. Use it for custom widgets (tabs, comboboxes, dialogs) to expose roles, states and relationships (aria-expanded, aria-controls, aria-live for dynamic messages). Also manage focus (trap it in modals, return it on close) and keep visible focus styles. Target WCAG 2.2 AA; test with keyboard only, axe, and a screen reader.

CORE<script> vs async vs defer vs type="module"?

A plain script blocks HTML parsing while it downloads and runs. async downloads in parallel and runs as soon as it's ready, in any order (analytics). defer downloads in parallel and runs in order after parsing (app scripts). Module scripts are deferred by default.

CORECompare cookies, localStorage, sessionStorage and IndexedDB.

Cookies (~4 KB) are sent with every request to their domain and can be HttpOnly (hidden from JavaScript), so they suit session identifiers. localStorage (~5 MB, persistent) and sessionStorage (per tab) are synchronous key-value stores readable by any script, so never put tokens there. IndexedDB is asynchronous, larger and structured, for offline data.

CSS3 5 questions

Layout systems and the cascade. Modern CSS features are a plus.

COREExplain the box model and box-sizing.

Every element is content + padding + border + margin. With the default content-box, width sets the content only, so padding and border add to it. border-box includes padding and border in the width, which is easier to reason about; most resets apply *, *::before, *::after { box-sizing: border-box; }. Vertical margins between blocks can collapse; flex and grid gaps avoid that.

COREHow is specificity calculated? How do you avoid specificity wars?

Order of weight: inline styles, then IDs, then classes/attributes/pseudo-classes, then elements/pseudo-elements. Equal specificity: the later rule wins. !important overrides all and should be rare. Keep specificity flat with single-class selectors (BEM, CSS Modules, or utility classes), and use cascade layers (@layer reset, base, components, utilities;) to control precedence explicitly. :where() adds zero specificity.

COREFlexbox vs Grid: when do you use each?

Flexbox is one-dimensional: laying out items in a row or column, distributing space, aligning (toolbars, nav bars, button groups, centering). Grid is two-dimensional: rows and columns together (page layouts, card galleries, forms). They combine well: a grid page with flex components inside.

.cards { display: grid; grid-template-columns: repeat(auto-fill, minmax(240px, 1fr)); gap: 1rem; }

SENIORWhy doesn't my z-index: 9999 work?

z-index only compares elements within the same stacking context. A new context is created by positioned elements with a z-index, and also by opacity < 1, transform, filter, isolation: isolate and others. A child can never rise above its parent's context. Fix it by moving the element (render modals in a portal at the document root) or adjusting the parent's context.

SENIORWhich modern CSS features do you use?

Custom properties (--brand) for theming and dark mode, container queries (@container), :has() (parent selector), native nesting, clamp() for fluid sizing, logical properties (margin-inline), aspect-ratio, gap in flexbox, prefers-color-scheme and prefers-reduced-motion media features.

Responsive UI Development 4 questions

They want a process: mobile-first thinking, fluid layouts, and performance on real devices.

COREHow do you approach building a responsive UI?

  • Include <meta name="viewport" content="width=device-width, initial-scale=1">.
  • Mobile-first: base styles for small screens, then @media (min-width: …) to enhance.
  • Choose breakpoints where the content breaks, not for specific devices.
  • Use fluid layouts (grid with minmax, flex-wrap), relative units (rem, %, vw), and max-width on media.
  • Touch targets at least ~44px; don't rely on hover.

SENIORMedia queries vs container queries?

Media queries respond to the viewport. Container queries respond to the size of a parent container, so a component (a product card) adapts to wherever it's placed, sidebar or main column. This makes components truly reusable.

.card-wrap { container-type: inline-size; }
@container (min-width: 400px) { .card { display: grid; grid-template-columns: 120px 1fr; } }

SENIORHow do you make images and typography responsive?

Images: srcset and sizes so the browser picks the right resolution, <picture> for art direction or modern formats (AVIF/WebP), explicit width/height or aspect-ratio to avoid layout shift, loading="lazy" below the fold. Typography: rem units to respect user font settings and fluid sizes with clamp(): font-size: clamp(1.5rem, 1rem + 2vw, 2.5rem);

SENIORHow do you measure front-end performance?

Core Web Vitals: LCP (Largest Contentful Paint, loading, target ≤ 2.5 s), INP (Interaction to Next Paint, responsiveness, ≤ 200 ms; it replaced FID in 2024) and CLS (Cumulative Layout Shift, ≤ 0.1). Measure with Lighthouse, Chrome DevTools and real-user monitoring. Improve with code splitting, image optimization, caching, and avoiding long main-thread tasks. Test on real mid-range phones and slow networks, not just DevTools resizing.

State Management (Redux, Context API) 5 questions

The key signal: you distinguish server state from client state and pick the lightest tool that works.

COREWhat kinds of state exist in a React app, and where should each live?

  • Local UI state (an open dropdown, a form input): useState/useReducer in the component.
  • Shared client state (theme, current user, cart): lift state up, Context, or a store (Redux Toolkit, Zustand).
  • Server state (data from the API): a cache library such as TanStack Query or RTK Query, which handles caching, refetching and invalidation.
  • URL state (filters, page, selected tab): the router's search params, so it survives refresh and can be shared.

SENIORWhat are the pitfalls of the Context API?

Every consumer re-renders when the context value changes, and an object literal as the value changes on every provider render. Mitigations: memoize the value with useMemo, split contexts by concern or by change frequency (separate state and dispatch contexts), and keep frequently changing data out of a widely used context. Context is a dependency-injection mechanism, not a full state manager; for complex, frequently updated global state use a store with selectors.

SENIORExplain Redux and how Redux Toolkit simplifies it.

Redux keeps global state in one store; components dispatch actions; pure reducers compute the next state; components read with selectors. It's predictable and debuggable (DevTools, time travel). Redux Toolkit is the standard way to write it today: configureStore, createSlice (generates actions and reducers; Immer lets you write "mutating" code that produces immutable updates), createAsyncThunk for async logic, and RTK Query for data fetching and caching.

const cartSlice = createSlice({
  name: 'cart',
  initialState: { items: [] as CartItem[] },
  reducers: {
    added(state, action: PayloadAction<CartItem>) { state.items.push(action.payload); },
    removed(state, action: PayloadAction<string>) {
      state.items = state.items.filter(i => i.id !== action.payload);
    },
  },
});

SENIORRedux vs Context vs Zustand vs TanStack Query: how do you choose?

If most "global state" is server data, TanStack Query or RTK Query removes most of it, and what remains is small enough for Context or Zustand. Choose Redux Toolkit for large apps with lots of shared, interdependent client state, many developers, and a need for strict conventions and DevTools. Zustand is minimal boilerplate with selector-based subscriptions. Context alone fits low-frequency values like theme, locale and auth user.

COREWhy must state be updated immutably?

React and Redux detect changes by reference comparison. Mutating an array or object in place keeps the same reference, so the UI may not re-render and memoization breaks. Create new objects: setItems(prev => [...prev, item]), {...user, name}. Use the functional updater form when the new state depends on the previous one.

API Integration 5 questions

Where front end meets your backend. Show you handle failures, cancellation, auth and typing end-to-end.

COREHow do you structure API calls in a React app? fetch or Axios?

Put calls in an API layer (one module per resource), not inside components, with a shared client that sets the base URL, headers, credentials and error handling. fetch is native but doesn't reject on HTTP errors; check response.ok. Axios rejects on non-2xx, has interceptors and automatic JSON. Either is fine; then use TanStack Query or RTK Query in components for loading, error, caching and retries.

async function api<T>(path: string, init?: RequestInit): Promise<T> {
  const res = await fetch(`${BASE_URL}${path}`, {
    ...init, credentials: 'include',
    headers: { 'Content-Type': 'application/json', ...init?.headers },
  });
  if (!res.ok) throw new ApiError(res.status, await res.json().catch(() => null));
  return res.status === 204 ? (undefined as T) : res.json();
}

SENIORHow do you avoid race conditions when a user changes a filter quickly?

Responses can arrive out of order, so an old response may overwrite newer results. Solutions: cancel the previous request with AbortController in the effect cleanup, ignore stale responses with a flag, debounce the input, or use TanStack Query, which keys queries by parameters and handles this. Pass the abort signal through and have the ASP.NET Core endpoint honor its CancellationToken.

COREWhat is CORS and how do you configure it with an ASP.NET Core API?

Browsers block cross-origin responses unless the server allows the origin. For non-simple requests (custom headers, JSON, PUT/DELETE) the browser first sends a preflight OPTIONS request. CORS is enforced by browsers only; it's not server security.

builder.Services.AddCors(o => o.AddPolicy("spa", p => p
    .WithOrigins("https://app.example.com")
    .AllowAnyHeader().AllowAnyMethod().AllowCredentials()));
app.UseCors("spa");

You can't combine AllowAnyOrigin with credentials. Serving the SPA and API from the same origin (or through a BFF/reverse proxy) avoids CORS entirely.

SENIORHow do you handle auth tokens and expired sessions in API calls?

With a BFF, the browser sends the session cookie automatically (credentials: 'include') plus an anti-forgery header. With bearer tokens, an interceptor attaches Authorization: Bearer …; on 401 it refreshes the token once, queues concurrent requests during the refresh, retries them, and redirects to login if refresh fails. Distinguish 401 (log in again) from 403 (show "not allowed").

SENIORHow do you keep front-end types in sync with the backend API?

Generate clients and types from the backend's OpenAPI document (built into .NET 9+) with NSwag, openapi-typescript or Orval, in the build pipeline so contract changes break the build instead of production. Validate critical responses at runtime with Zod, since types don't exist at runtime. Map ProblemDetails errors into a typed error the UI can display, including field-level validation messages.
