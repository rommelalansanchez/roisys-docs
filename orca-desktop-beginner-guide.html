Orca Desktop · Beginner Quick Start

Learn the 20% you’ll use 80% of the time.

Orca is a desktop IDE for running AI coding agents side-by-side. Each task gets a real Git worktree, so Claude Code, Codex, Cursor CLI and other agents can work independently without overwriting one another.

Repo → Worktree → Agent → Review diff → Commit / Push → PR

1. One-time setup

1

Install your agent CLI(s)

Install and log into Claude Code, Codex, or another CLI outside Orca first. Orca reuses those local credentials.

2

Add your repo

Open Orca → Add Repo → select your existing local Git checkout. Orca uses your default branch as the base reference.

3

Check permissions

Go to Settings → Agents → Agent Permissions. Choose Manual for normal approvals or Yolo for fewer prompts.

4

Pick defaults

In Settings → Agents, enable the CLIs you want and choose your normal default agent.

Important: Orca defaults supported agents to permission-bypass launch flags. Worktrees reduce risk to your main checkout, but agents can still run commands. Use Manual if you want approval prompts.

2. Your normal workflow

1

Create a workspace/worktree

Click + beside the repo. Give the task a name such as fix-login-race. Usually branch from origin/main.

2

Launch an agent

Choose Claude Code, Codex, Cursor CLI, etc. Orca launches it with that worktree as its working directory.

3

Give it the task

Prompt the agent normally. You can create more worktrees and give the same prompt to several agents to compare solutions.

4

Review, revise, ship

Open Diff, inspect changes, leave review notes, send notes back to the agent, then stage → commit → push.

3. Worktrees: the key Orca concept

Each workspace is a real git worktree with its own branch, files and agent terminals. That isolation is what makes parallel agents practical.

  • Base ref: normally origin/main.
  • Start-from ref: what a new worktree branches from; it can also be another branch or commit.
  • Deleting a workspace: can remove its worktree and branch, so review before confirming.
  • Gitignored files are not automatically present: new worktrees may be missing .env, caches, local config or dependencies.

For repeated setup, use Settings → Repository → Worktree Shared Paths, worktree.sharedDirectories in orca.yaml, or .worktreeinclude.

4. Running several agents

A useful Orca pattern is to create 2–3 worktrees for the same problem, run a different agent/approach in each, then compare their diffs.

Drag a tab to the right edge for a left/right split, or the bottom edge for a top/bottom split. Each worktree remembers its own layout.

5. Review code before accepting it

Diff viewer

Shows staged, unstaged and untracked changes. You can stage by file, hunk or line and resolve merge conflicts visually.

Annotate AI Diff

Hover a changed line → click + → leave feedback. When finished, click Send to agent to send all review notes together.

Commit & push

Stage changes, write or AI-generate a commit message, commit, then push. Orca does not silently force-push.

6. Browser + UI work

Every worktree can have its own embedded Chromium browser, so your local app stays tied to the task you are working on.

Design Mode is especially useful for frontend bugs: enable it in the browser toolbar → click a UI element → Orca sends its HTML, computed CSS, screenshot and (when available) source location to the active agent.

8. Desktop features worth enabling later

Chat UI · Experimental

Settings → Experimental → Chat UI. Gives supported agents a structured chat-like interface. The terminal remains the source of truth.

Agent Dashboard · Experimental

Shows agents grouped by states such as Needs You, Working and Done. Handy once you regularly run several sessions.

10. When something breaks

Agent will not start

Run the same CLI in a normal terminal. If it fails there, fix installation/login first. If it only fails in Orca, check Settings → Agents, confirm the CLI is on Orca's PATH, then try the tab's Restart action.

Worktree creation fails

Run git fetch origin. Also check whether that branch already has another worktree.

Diff looks stale or wrong

Click the refresh button in the diff toolbar, especially after external Git operations such as rebase or reset.

Orca uses too much RAM

Close worktrees you are not using. Worktrees keep file watchers alive, and layouts with many browser tabs consume the most memory.

The beginner checklist

  • ✓ Install + log in to your agent CLI(s).
  • ✓ Add your Git repo.
  • ✓ Decide Manual vs Yolo agent permissions.
  • ✓ Create one worktree per task/approach.
  • ✓ Let agents work only inside their worktrees.
  • ✓ Review the diff before committing.
  • ✓ Use review annotations to send precise fixes back to the agent.
  • ✓ Commit/push only the solution you want to keep.
  • ✓ Delete/archive unused worktrees when finished.
